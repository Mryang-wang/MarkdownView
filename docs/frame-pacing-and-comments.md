# 掉帧优化与批注交互

2026-10-12，Windows、Python 3.12、PySide6 / Qt WebEngine 6.11.1。基于 1.3.5 继续修改源码，本轮不生成安装包。

后续已随 1.3.6 打包，见 [安装包验证](release-1.3.6.md)。下文保留源码优化阶段的测量记录。

## 改动

- 即时渲染中的普通段落文字输入，在符合条件时保留原有文本节点，使用 Vditor 自身的输入、提示和撤销调度。Markdown 标点、段首、选区替换、粘贴和输入法组合继续走原解析流程；临时光标碎片达到上限时也交回原解析器整理。
- 普通文字变化不再重复扫描整篇字体、下划线标记。标记或段落结构变化仍刷新对应格式；多段 HTML 格式继续保留全文检查。
- 批注和字数统计共用可失效的正文文字索引；批注刷新不再转换整篇 Markdown 判断变化。模式切换前先处理尚未刷新的锚点，再按新模式重新定位。
- 大型 Markdown 转换快照先在脱离页面的副本中清理公式、代码等预览内容，保留原始标记，再交给 Lute。编辑器本身及其撤销快照不被这一步改写。
- 工具栏换行时一次确定实际高度，使用位移衔接正文的位置；取消逐帧改变高度的动画。跨行的按钮采用短距离淡入，避免从其他图标上方穿过。
- 侧栏动画期间保留较宽的编辑器画面，通过父容器裁切和平移；收起时在开始、展开时在结束提交一次编辑器宽度。正文仍是可交互的真实编辑器，不使用截图、文字缩放或离屏副本。保留快速反向操作、窗口缩放、隐藏及全屏处理。
- 移除重复的整块工作区重绘请求；隐藏的批注、翻译面板不再参与尺寸测量。
- 批注按照原文起始位置排列，同起点按结束位置排列，同一选区维持稳定顺序。原文已删除的批注保留并排在末尾；排序不改变批注 ID 或保存内容。
- 移除独立的“编辑”按钮，双击批注正文打开文本框。Tab 聚焦批注后，Enter / 空格也可编辑；保存、取消和 Escape 保留。重新排序时保留正在编辑的草稿及焦点。

## 方案参考

参考 GitHub 的 [60fps-animation 技能](https://github.com/iart-ai/web-animation-skills/tree/main/skills/60fps-animation) 与 [FastDOM](https://github.com/wilsonpage/fastdom) 关于位移动画、集中读取布局与避免重复重排的做法，并对照 [Vditor 的选区实现](https://github.com/Vanessa219/vditor/blob/master/src/ts/util/selection.ts) 排查输入开销。

采用现有 Qt、浏览器和 Vditor 能力，没有引入新的动画运行库，也没有修改第三方打包脚本。新技能安装在本机 Codex 技能目录，不进入应用安装包；下轮对话即可使用。

## 实测与边界

输入测量使用同一份 600 段、600 个公式及字体、下划线、行距标记的文档，约 13.4 万字节、4.1 万个 DOM 元素；通过 Qt 发送真实按键，记录 Chromium 帧回调和 CPU。交互测量另外使用 300 段、900 个公式的文档。

交互测量使用 Qt 事件循环调度，在隔离目录读取提交 `6ef6c65` 作为基线，测试源文件和参数保持一致；初期使用 10 ms 轮询的探索结果不与这组帧率混合比较。输入测量前后使用同一套按键与等待方式。

| 测量项目 | 1.3.5 基线 | 当前源码 |
| --- | ---: | ---: |
| 侧栏三次收起／展开：编辑器宽度变更次数 | 22 | 6 |
| 同一侧栏操作：浏览器总处理时间 | 914.7 ms | 468.3 ms |
| 同一侧栏操作：帧间隔 P95 | 200.0 ms | 149.9 ms |
| 四次未修改正文的批注刷新：脚本总耗时 | 2126.4 ms | 5.2 ms |
| 同一批注操作：帧间隔 P95 | 550.0 ms | 16.8 ms |
| 连续滚动：帧间隔 P95 | 33.3 ms | 33.3 ms |
| 流式译文预览：帧间隔 P95 | 16.7 ms | 16.7 ms |
| 大型 Markdown 转换：八次调用的中位数 | 569.1 ms | 397.4 ms |
| 长文输入：帧间隔 P95 | 116.6 ms | 83.3 ms |

P95 表示 95% 的采样帧间隔不超过该数值；总处理时间是整个测量区间的累计值，不是每次点击的响应延迟。侧栏累计处理开销下降约 49%，但压力文档仍存在超过 50 ms 的帧。普通输入到下一次帧回调的中位时间从 37.0 ms 降到 1.2 ms，P95 则为 40.0 ms → 41.2 ms，并非所有输入都同比改善。空闲检查没有残留运行中的动画。

对应原始结果为 `baseline-eventloop-interactions.json`、`verified-eventloop-interactions.json`，以及 `tmp/smoothness/before-1.3.6.json`、`tmp/smoothness/final.json`。

测量数据位于本地 `tmp/smoothness/` 与 `tmp/performance-1.3.6/`。帧回调受原生窗口缩放、绘制、桌面负载影响；输入到下一帧的时间也不等于输入到屏幕显示的完整延迟。结果不应解读为所有设备稳定 60 fps。

超长富文本仍需在保存、复杂 Markdown 输入及撤销时处理文档；侧栏切换边界的正文换行、Qt 原生绘制也仍有开销。此次减少了可重复确认的多余计算，没有保证所有场景完全消除掉帧。

## 验证范围

18 个相关功能回归脚本最终通过，另完成 1 个实际窗口的动画截图检查；Python 编译检查和 `git diff --check` 通过。

实际 Qt / WebEngine 窗口检查涵盖文字输入与段尾空格、Markdown 语法、输入法组合、撤销重做、同步保存取值、两种富文本模式的快照转换一致性；字体、字号、颜色、行距、表格、Word / PDF 导出、翻译阅读位置与同步滚动、多文档及状态栏。

批注检查包括逆序添加、同一选区多条批注、已删除原文的批注排序、真实 Qt 双击、键盘编辑、保存与取消、31 条批注的正文高亮、草稿和焦点保留、保存重开、三种编辑模式及中英文界面。

动效检查包括三种窗口宽度、每次切换仅一次编辑器宽度变化、快速反向切换、动画中调整窗口尺寸、全屏及隐藏窗口、深浅主题、系统关闭动画、滚动位置与内容保留，以及动画结束后的清理。实际 Qt 窗口另外截取了两种主题下展开／收起的起始、中途及结束画面。本地测试脚本和测量产物继续排除在 Git 仓库之外。

观察项：翻译从逐段显示切换到整篇回退渲染时，曾记录一次原文滚动位置约 60 px 的偏移，仍位于同一段落；随后两次独立复查通过，尚未稳定复现。保留为待观察的问题，不将其记为已修复。
