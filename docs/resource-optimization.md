# 资源实测与优化说明

本文保留本地测量方法与历史验证记录。测试、基准和安装验证脚本及 `tmp/` 输出不纳入公开仓库；下述脚本命令仅适用于维护者本地环境。

## 1.3.0：页内翻译与统一弹窗（2026-10-07）

翻译侧栏与全文对照阅读复用当前文档的 WebEngine，不创建额外浏览器窗口，也没有添加第三方依赖。选区和全文流式字符以 100 ms 合并刷新，每次只传当前生成部分，不重排整份文档或重复渲染公式。完成分段后更新正式排版。左右对照编辑复用原有编辑器，窄窗口上下排列；双语阅读中未变化的代码、公式和图片只显示一次。后台标签页停止内容刷新，关闭任务时取消网络请求；已完成并隐藏的翻译页面允许阅读缓存释放，返回标签页恢复结果。

左右同步滚动使用被动事件监听和动画帧合并，按区块位置二分定位，只读取少数区块的几何信息；下一帧校正新进入视口的按需排版高度，保留 `content-visibility`。程序联动产生的滚动事件不会反向触发同步，不运行常驻轮询，也不调用模型。顶部停止按钮复用已有取消／续译流程，不增加请求队列。

手动“更新改动”使用当前文档会话内的句段缓存，不建立常驻服务或全局索引。先线性比较公共前后缀，再对受限的改动区域做匹配；修改一句不重新提交整份文件。上下文每侧最多 240 字符，仅保留放得下的完整句段；待翻译的完整句段合并发送，单句超限先提示，不硬切或放大预算。不变、删除和独立代码变动在本地处理。分句使用本地轻量规则，没有增加 NLP 库、模型文件或额外网络调用，合批上限不影响缓存边界。缓存随文档关闭释放，模型／语言／提示词／术语变化不复用旧译文。测试与限制见 [增量翻译说明](features-1.2.md#手动更新改动减少重复请求)。

统一弹窗使用现有 Qt 控件和共享样式。翻译配置和密钥仍只在原生层使用；通过 `MDVIEW_DATA_DIR` 显式指定独立资料目录时，设置也使用该目录下的独立 INI 文件，避免测试读取日常配置。未设置该环境变量时沿用原来的设置位置。

同一份 600 个公式、45,998 字节的编辑基准，第一次测量全文索引／查找／下一匹配中位数为 **7.9 / 8.4 / 3.1 ms**；查找 p95 出现 **83.7 ms** 尾部波动，因此在开始构建前复测，中位数为 **7.1 / 8.5 / 3.2 ms**，查找 p95 为 **18.2 ms**。两次结果都保留在 `tmp/editor-benchmark/release-1.3.0*.json`；这不是帧率或真实模型响应时间的保证。

28 个源码回归脚本通过，新增检查包含分段失败后续译、双语区块、公式／表格／图片、标签页与缓存、窄窗口、深浅主题以及统一弹窗。按用户要求暂缓生成安装包，最终安装体积和安装／升级／卸载结果留待修改收尾后记录。

## 1.2.0：增加功能后的资源控制（2026-10-06）

翻译复用 QtNetwork，不引入模型 SDK、模型权重或新的第三方依赖。请求异步执行，分段串行发送，译文以 100 ms 为间隔合并刷新；取消和失败会停止网络请求。项目搜索只在用户查询时启动可取消的后台扫描，限制文件数、文件大小和结果数量。Word 导出、差异计算和 ZIP 打包在后台执行。历史快照默认每文档 20 份、总计 50 MB，自动保存历史每分钟最多写一次，可调整配额。

大文档可使用源码轻量模式，避免公式的即时渲染，将实时统计间隔从 150 ms 调整为 1,500 ms；原有阅读缓存、编辑中撤销保留、查找去抖和相同会话免写盘策略继续有效。图片压缩为可选项，透明图片保留透明度，动画和 SVG 保留原文件。Word 和 PDF 使用临时输出成功后再替换目标，正常完成或异常时清理临时文件。

增加全部 15 项本地工具及翻译功能后，程序文件总量（未压缩）由 **401.719 MiB** 增至 **401.907 MiB**，增加约 **0.187 MiB**；安装器由 **113.773 MiB** 增至 **113.933 MiB**，增加约 **0.160 MiB**。没有通过删除公式、中文字体、Word/PDF 导出或图形兼容能力缩减体积。安装后的实际磁盘占用仍由 Windows LZX 压缩和文件系统决定。

沿用 600 个公式、45,998 字节的受控文档，停止构建后单独执行 `bench_editor.py --label release-1.2.0-final`：全文索引中位数 **6.9 ms**，查找 601 个匹配中位数 **8.0 ms**，跳转下一个匹配中位数 **2.9 ms**。与 1.1.5 保持相近水平；这些数据不是帧率，也不代表所有文档或第三方模型的响应时间。原始结果在 `tmp/editor-benchmark/release-1.2.0-final.json`。

新增功能与限制见 [1.2 使用说明](features-1.2.md)。源码回归包含 27 个脚本，日志记录在 `tmp/feature-validation/`；真实打包验证还检查翻译窗口的原生桥接、只读控制及独立打印快照。翻译使用本地模拟 SSE / JSON 服务检查取消、超时、错误、保留已完成部分后续译和加密存储，未使用真实用户密钥测量翻译质量。

## 批注定位与搜索取消优化（2026-10-07，未打包）

字号、字色等格式改变后，正文文字不变时不再重复计算所有批注的定位；正文编辑时，公共前后缀只计算一次并供各批注共享。项目搜索每进入一个目录都会检查取消状态，包含大量空目录或非文本目录的项目也能及时停止后台扫描。新增字体、字号、字色控件复用现有编辑器，不引入新运行库、额外渲染进程或字体包。

使用真实 `review_features.js` 在 QJSEngine 中运行 22,000 字符、100 条批注的定位微基准：只改变格式的定位计算由 1,066 ms 降至 1 ms，末尾编辑由 773 ms 降至 8 ms；正文不变时的全文重定位次数由 100 次降为 0 次。这是单项计算耗时，不代表整个界面的帧率或内存下降比例。原始数据在 `tmp/review-performance/latest.json`，回归脚本为 `test_review_performance.py` 与 `test_project_scan_cancellation.py`。

本轮源码版另测了同一份 23,565 字节公式文档的进程树：单文档私有提交约 765 MiB，8 份全部浏览后约 1,731 MiB、保留 3 个渲染进程，关闭其余 7 份后约 845 MiB、回到 1 个渲染进程。空闲 CPU 为整机的 0.028%–0.112%，本次已缓存文档切换约 140 ms。Qt WebEngine 的基础内存仍较高，这些当前数据不作为相较历史版本降低内存的证据。完整记录在 `tmp/resource-benchmark/text-styles-current.json`；以下保留以前版本的测量结果。

## 实测结果

测试文件为项目中的 `02_建模方法_SCI精简重构版.md`（23,565 字节），复制为 8 份不同路径的文档。测量应用进程及其所有子进程；内存使用 Windows `PrivateUsage`（私有提交内存），避免直接相加工作集时重复计算共享内存。它与任务管理器默认列显示的物理内存数值可能不同。

| 场景 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| 打开 1 份公式文档 | 638.8 MiB | 621.0 MiB | 基本相当 |
| 批量加入其余 7 份，尚未逐个浏览 | 2832.7 MiB | 1002.4 MiB | 减少约 65% |
| 8 份全部浏览过，保持打开 | 3157.2 MiB | 1386.0 MiB | 减少约 56% |
| 关闭其中 7 份 | 722.5 MiB | 639.1 MiB | 已释放其余渲染进程 |

全部浏览后，渲染进程由 8 个减少为 3 个。批量加入时由 8 个减少为 2 个（原来的当前文档和最后选中的新文档）。

测量前等待初次渲染结束，再采样 4 秒。优化前后空闲 CPU 均约 0.2%–0.4%，已按 14 个逻辑处理器归一化。初次打开公式文档时会有短暂 CPU 峰值，不能将其当成持续空闲占用。这些结果是一次受控实测，受系统缓存、分配器和文件内容影响，不代表所有文档的固定占用。

## 已完成的优化

1. 按需加载编辑器，合并批量打开和会话恢复中的中间选中事件。侧栏立即保留完整文档列表，无需同时启动全部渲染进程。
2. 全部窗口共用约 3 个编辑器的阅读缓存，优先回收较久未使用的未编辑后台页面。使用 [Qt 页面生命周期的 Discarded 状态](https://doc.qt.io/qt-6.11/qwebenginepage.html#lifecycleState-prop) 释放浏览上下文；源内容在内存中保留，切回时恢复编辑模式、大纲、预览状态和阅读位置。
3. 编辑过的文档（包括保存后的文档）保留完整编辑器，以保留撤销/重做记录。活动窗口中的当前文档、正在打印的文档，以及打开查找或格式面板的页面受到保护。缓存数量因此是软限制；同时编辑大量文档时占用仍会增加。
4. 字数统计合并为输入暂停 150 毫秒后更新，减少每次按键都转换整份 Markdown 的开销；脏标记和草稿保护仍及时触发。
5. 主题和侧栏状态仅在变化时发送到页面；图片观察器只检查新增节点；下划线/高亮遍历限制在选区所在子树，跳过空高亮并避免重复写入相同样式。

被回收的文档再次切回时需要重新渲染，因此会比一直保留的文档慢一些。未编辑页面恢复缓存中的原内容，不会悄悄读取后来被外部修改的版本；自动保存的外部修改检测继续使用原文件时间戳。

## 窗口缩放优化（2026-10-03，1.1.3）

缩放的主要开销来自应用级事件过滤器：WebEngine 内部大量对象创建、属性变化和布局事件都进入了 Python。现在只在主窗口、八个缩放控件、菜单栏和编辑器键盘接收控件上监听所需事件；文档拖到独立窗口时，截图粘贴事件也随编辑器转移。

最初的手动缩放优化以 16 毫秒为间隔合并鼠标位置，松开时立即应用最终位置。角部遮罩只创建一次，控件显隐和层级仅在窗口状态变化时更新，减少重复重绘。此机制现在只用于系统不支持原生缩放时的兼容回退。

最新修改优先调用 `QWindow.startSystemResize()`，让 Windows 接管四边和四角的交互缩放。原生路径不会启动 Python 缩放计时器或主动抓取鼠标，不再由程序反复设置窗口尺寸。Qt 官方也建议在系统支持时使用该接口替代交互过程中的 `setGeometry()`：[QWindow 原生缩放说明](https://doc.qt.io/qt-6/qwindow.html#startSystemResize)。正文继续实时排版，最小窗口尺寸保持 480 × 360。

本机使用同一份 72,171 字节的含公式长文档，定时发送 360 次 Qt 鼠标移动事件，沿相同轨迹往返缩放；均使用独立配置和临时文件，不操作系统鼠标。以下是受控压力测试结果，不代表实际拖动帧率或所有电脑的提升幅度。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 整组缩放事件处理时间 | 70.37 秒 | 6.25 秒 |
| 主进程累计 CPU 时间 | 67.41 秒 | 4.69 秒 |
| 鼠标事件处理耗时 P95 | 11.54 毫秒 | 0.26 毫秒 |
| 实际窗口尺寸更新次数 | 197 | 100 |

以上是上一阶段手动缩放的历史数据，不能作为原生缩放流畅度或重影改善的证据。原始记录为 `tmp/resize-benchmark/before.json` 和 `tmp/resize-benchmark/optimized.json`。运行 `.\.venv\Scripts\python.exe bench_resize.py --label current` 仅复测兼容回退路径；脚本明确禁用原生缩放，输出标注后端类型。基准不统计 WebEngine 子进程 CPU，也不使用不可用的帧率数据。

`test_native_window_resize.py` 使用真实 Windows 缩放循环验证八个方向、结束和 Esc 取消、最终尺寸、无后台计时器覆写、正文与阅读位置保留。测试仅向测试窗口发送消息，通过约束 `WM_SIZING` 的矩形来消除系统鼠标位置和 DPI 的影响，不控制全局鼠标，也不宣称测得视觉帧率。`test_window_resize.py` 单独验证兼容回退的八个方向、鼠标事件合并和释放时无延迟漂移。另复查滚动条操作、截图粘贴和文档拆窗。本节修改已纳入 1.1.3 安装包。

### 底部状态栏对齐与缩放定位

侧栏主题按钮与字数、编辑模式统一为 36 像素高的底部行，文字采用相同的 11 像素字号并垂直居中。桌面状态栏及其上方分隔线改由 Qt 直接布局、绘制，跟随窗口尺寸同步更新，不再依赖 WebEngine 下一帧完成网页重排；网页独立预览仍保留 HTML 状态栏。字数和模式只在变化时经 QWebChannel 更新，每个文档单独保存状态，后台文档不会覆盖当前状态栏。点击字数仍可查看全文或选中文字统计。

`test_editor_status.py` 在测试编辑器渲染线程暂时忙碌时连续改变 18 次窗口尺寸，逐次检查底部位置及文字对齐，并检查浅色/深色分隔线实际像素、文档切换与拆窗、语言、窄窗口、隐藏侧栏和全屏。此测试验证底部布局不等待网页重绘，不测量帧率。选中文字统计与批注回归见 `test_review_language.py`，缓存恢复后的字数与模式检查见 `test_resources.py`。这些修改已随 1.1.3 打包发布。
