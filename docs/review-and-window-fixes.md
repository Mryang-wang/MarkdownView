# 1.3.3 批注与 Windows 分屏修复

验证环境：2026-10-09，本机 Windows、Python 3.12、PySide6 / Qt WebEngine 6.11.1，屏幕缩放 200%。

## 批注

- 添加批注时不再向已经关闭的翻译面板重复发送退出操作。关闭全文翻译后仅恢复一次编辑器焦点，并禁止焦点操作自动滚动，避免异步退出回调抢走批注输入框焦点、将正文带回文首。
- 每条批注右上角新增“编辑”；在卡片内修改后选择“保存修改”或“取消”，也可按 Esc 取消。空内容不能提交，修改已有批注保留原来的 ID 和原文关联。
- 刷新批注列表时复用已有卡片和输入框；更新原文、切换主题或界面语言时保留正在输入的内容、选区和光标。
- 修复整段选区结束在下一段开头时没有正文高亮的问题：索引中的段落分隔符没有对应的 DOM 文本节点，现在用与选区重叠的实际文字生成高亮范围。

用户报告的现象是即时渲染模式下新增批注偶尔没有标记，随后又恢复；本轮稳定复现并修复了上述段落边界问题。连续新增 31 条普通选区批注及第 32 条段落边界批注均有高亮，未发现仅由数量达到 31 条触发的丢失问题。

## Windows 窗口

保留无边框外观，在主窗口显示时补回 Windows 原生 `WS_THICKFRAME` 缩放标志。Qt 原本的无边框配置省略了该标志，导致已有的 `startSystemMove()` 拖动无法触发贴靠。

- 拖动顶部菜单栏空白处到屏幕左右边缘，使用 Windows 分屏。
- 支持 `Win + ← / →`；最大化、还原和退出全屏后继续可用。
- 沿用现有原生窗口移动、缩放路径；不引入依赖、后台轮询或模拟分屏实现。

实现依据：[Qt 原生窗口拖动文档](https://doc.qt.io/qtforpython-6/PySide6/QtGui/QWindow.html#PySide6.QtGui.QWindow.startSystemMove)和 [Qt 6.11.1 Windows 窗口实现](https://github.com/qt/qtbase/blob/v6.11.1/src/plugins/platforms/windows/qwindowswindow.cpp)。

## 回归范围

7 个相关本地源码回归脚本通过，覆盖：

- 200 段长文中从中间位置新增批注，滚动位置保持；连续新增批注和段落边界高亮。
- 从全文翻译切换到添加批注，原生异步退出回调返回后仍保留输入焦点、批注内容和正文位置。
- 批注编辑、保存、取消、Esc、空内容校验、保留草稿、文件保存重开、三种编辑模式、浅深色和中英文界面。
- 批注定位、重复原文、删除原文后的失效提示、元数据转义、原文变更后的锚点更新。
- Windows 真正的边缘鼠标拖动、左右快捷键分屏、最大化／还原、全屏恢复，以及八个方向的真实鼠标缩放。
- 原有窗口边缘绘制、正文缩放、文档分离；翻译侧栏与全文对照、流式更新期间的滚动位置、模式及窄窗口切换。

旧的仅向 HWND 投递鼠标消息的缩放测试，在增加原生缩放标志后没有产生实际 `WM_SIZING`，不能用于判定新的原生路径；本轮改用真实鼠标按下、移动、释放，验证八个方向的窗口矩形变化。

测试脚本、截图和日志仅保留在本地，不随安装包或仓库发布；窗口测试没有修改系统贴靠设置。
