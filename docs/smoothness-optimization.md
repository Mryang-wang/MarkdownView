# 1.3.2 流畅度优化记录

验证日期：2026-10-09。环境为本机 Windows、Python 3.12、PySide6 / Qt WebEngine 6.11.1。

## 修改

- 格式观察器记录改动的顶层段落、列表或表格；普通局部编辑只刷新这些区域的字体和段落样式，并复用未改变的下划线、高亮范围。整篇替换、多块批量修改和跨段 HTML 格式标记回退到全文处理。
- 使用弱引用缓存解析过的格式标记；标记文字变化后重新解析。遍历正文时整棵跳过公式预览与编辑器标记子树，避免逐一检查 KaTeX 的所有节点。
- 保存格式选区时计算文字位置，避免复制从文首到光标的全部 DOM。格式绘制自身产生的 DOM 变化不再安排一次重复刷新。
- 普通编辑时，至少 160 个顶层块的可视编辑文档使用浏览器 `content-visibility: auto`，减少屏幕外内容的布局工作；已测量高度由浏览器保留。完整正文仍在 DOM 中，可查找、选中、编辑与导出。全文翻译对照时原文使用完整布局，打印样式也不使用此优化。
- 状态栏字数从可见正文计算；打开详细统计时再提取 Markdown，以保留原有行数、段落数统计。移除不执行任何操作但会触发全文提取的失焦回调。
- 未进入全文对照编辑时，翻译滚动监听器直接返回，避免每次按键都检查编辑区高度。
- 长文翻译更新时，除原文位置外还保存右侧可见译文段落与段内偏移，避免前面段落高度变化导致右侧偏移。手动滚动可取消待执行的位置恢复，包括仅显示译文的模式。

未增加运行依赖、网络请求或后台轮询；保留原有草稿备份、自动保存和文档缓存策略。

## 对照测量

使用相同生成文档：600 段、600 个公式、每段包含字体颜色、下划线及行距设置，文件 134,202 字节、约 41,478 个 DOM 元素。实际启动桌面编辑器，通过 Qt 输入事件连续输入同一段文字，同时用 Chromium CPU profiler 和 `requestAnimationFrame` 记录响应。测量时没有同时构建或运行其他回归测试。

| 项目 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 强制全文格式刷新，中位数 | 82.7 ms | 56.0 ms |
| 强制全文字体刷新，中位数 | 38.3 ms | 20.7 ms |
| 强制全文段落样式刷新，中位数 | 19.0 ms | 9.4 ms |
| 输入测试帧间隔 P95 | 816.7 ms | 100.0 ms |
| 浏览器 input 事件至下一帧，P95 | 151.2 ms | 37.7 ms |

全文格式刷新约减少 32%；普通单段编辑另外使用局部刷新路径。帧间隔和 input 至下一帧来自一次相同脚本的压力测试，受系统调度、输入事件合并和 Chromium 排版影响，不能视为所有文档的固定帧率或物理按键延迟。该高密度文档仍存在长帧，全文 Markdown 提取仍约需 0.6 秒；本轮主要减少输入期间不必要的处理，不宣称消除了全部卡顿或降低了 Qt WebEngine 的基础内存。

原始日志和 CPU profile 保存在本地 `tmp/smoothness/`；基准脚本、回归脚本及输出均不上传仓库。

## 功能回归

15 个相关本地回归脚本通过，覆盖：

- 增量格式更新、格式标记删除、跨段 HTML 格式及其删除后的清理、输入法结束时重绘。
- 即时渲染及所见即所得模式中的长文远处查找、编辑、滚动位置与保存。
- 字体、字号、文字颜色、五种下划线、高亮、对齐和行距、撤销／重做、表格操作、Word / PDF 导出。
- 选中文字统计、详细段落统计、纯图片文档提示、批注、界面语言、编辑保存。
- 翻译侧栏、开始／停止、流式更新、同步滚动与阅读位置、文档缓存及草稿保护。

另将翻译滚动测试从 65 段扩大到 180 段，覆盖分段完成、全文布局回退、恢复逐段布局、缩放、源代码模式、窄窗口、仅显示译文及用户主动滚动。该压力测试发现并修复了右侧译文段落因前文高度变化而偏移的问题。最终回归日志位于本地 `tmp/validation-smoothness/`。
