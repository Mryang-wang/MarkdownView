# 最大化拖动与顶部菜单修复

2026-10-12，Windows、Python 3.12、PySide6 / Qt WebEngine 6.11.1。在现有源码改动上继续修复，未生成安装包。

后续已随 1.3.6 打包，见 [安装包验证](release-1.3.6.md)。

## 改动

- 最大化时按下顶部菜单栏空白处，移动超过系统拖动阈值才还原窗口；单击和小幅移动不会误触还原。按下后松开、窗口隐藏或失去激活状态会取消等待中的拖动。
- 还原时保留此前的窗口尺寸，并按鼠标在标题栏中的横向比例定位窗口，随后交给 Windows 原生拖动处理。继续支持拖至屏幕边缘分屏。
- 还原位置使用 `normalGeometry()` 中的宽度计算，避免 `showNormal()` 后 Qt 尺寸事件尚未到达时误用最大化宽度。
- 最大化按钮改用矢量图标：普通状态显示单方框，最大化状态显示双层方框。提示和无障碍名称同步显示“最大化窗口”或“还原窗口”，支持主题及界面语言切换。
- 顶部菜单增加 4 个逻辑像素的上方留白，菜单栏高度设为 34 个逻辑像素。保留现有菜单、应用图标及右上角窗口按钮布局。

## 验证

以下 5 个本地脚本通过，测试使用隔离设置与临时文档；脚本、日志及截图不提交仓库。

| 检查 | 结果 |
| --- | --- |
| `test_window_caption.py` | 拖动阈值、还原尺寸与定位、原生移动调用、松开及失去激活后取消、双击切换、图标与提示、中英文与浅深主题、全屏返回及正文保留通过 |
| `test_native_caption.py` | Windows 200% 显示缩放下，从最大化标题栏两个不同位置实际拖动，均还原到原尺寸并持续跟随鼠标；从最大化直接拖至屏幕左侧后分屏成功 |
| `test_window_snap.py` | 真实鼠标边缘吸附、Win + 左／右分屏、最大化与还原、全屏返回后分屏、全部八个方向的原生缩放通过 |
| `test_window_resize.py` | 缩放回退路径、连续移动合并、松开后的最终尺寸、窗口按钮与边角命中区域通过 |
| `test_window_chrome_zoom.py` | 浅深主题、侧栏显示／隐藏、页面缩放、编辑模式、全屏、文档切换与分离窗口通过 |

另外检查了浅深主题截图、Python 编译及 `git diff --check`。真实鼠标测试仅向已确认处于前台的测试窗口发送输入，结束后还原鼠标位置。本轮没有重新测量全套编辑性能，也未覆盖不同 DPI 的多显示器切换。

## 实现参考

Qt 的 [`QWindow.startSystemMove()` 文档](https://doc.qt.io/qt-6/qwindow.html#startSystemMove)建议使用系统移动来保留窗口管理器交互。[本项目使用的 Qt 6.11.1 Windows 实现](https://github.com/qt/qtbase/blob/v6.11.1/src/plugins/platforms/windows/qwindowswindow.cpp)通过投递系统移动消息启动拖动；本次在调用前处理无边框最大化窗口的还原，不替换 Windows 后续拖动与吸附流程。
